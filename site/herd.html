The guide

Start a herd.

Six things turn a pile of computers into a herd. They go in this order, because each one assumes the last. None of them needs Little Herd, and none of them takes an afternoon.

Everything here is built into macOS, free, or open source. Where there is one mistake that costs an evening, it is called out — most of these look like they worked right up until the moment they matter.

  1. 1

    One network

    Tailscale — every machine gets one name that works from anywhere.

    This is first because everything below assumes you can reach the machine. Install it on each one, sign in with the same account, and turn on MagicDNS. Now ssh mini works from the sofa, from a hotel, and from another machine in the herd — without port forwarding, without a static IP, and without exposing anything to the open internet.

    The trap: a machine’s key expires by default, usually in about six months. A laptop you use daily just asks you to sign in again. An unattended box silently drops off the network and you discover it the next time you need it, which is the worst possible moment. Disable key expiry for anything headless.

    And: a .local name is mDNS. It resolves at home and nowhere else, so a setup tested only on the sofa looks finished and fails the first time you leave the house. Use the tailnet name everywhere, including in scripts.

  2. 2

    One way in

    SSH, with a config file — short names instead of addresses you have to remember.

    Generate a key, copy it over with ssh-copy-id, then write the machine down in ~/.ssh/config once:

    Host mini
  HostName mini.your-tailnet.ts.net
  User you

    From then on it is ssh mini, and so is scp file mini:, and so is everything else that speaks SSH. Keep that file in your dotfiles and Include it, so a new machine inherits the whole herd instead of being configured by hand.

    The trap: a key with a passphrase cannot be used by anything that runs unattended — there is nobody there to type it. Keep your passphrase key for sitting-at-the-keyboard work, and give scheduled jobs their own passphrase-free key, authorised for exactly the one link it needs. A single key for both is how a convenience becomes the blast radius.

    And: SSH silently ignores a config or key file that other users can write. Wrong permissions do not produce an error that says “permissions” — they produce Permission denied (publickey), which sends you off debugging the key instead. chmod 600.

  3. 3

    The same tools everywhere

    Homebrew and a Brewfile — so a machine is somewhere you can actually work, not somewhere missing your tools.

    A herd whose members each have a different half of your toolkit is still a pile. Dump what you have into a list, keep the list in your dotfiles, and install from it on every machine:

    brew bundle dump --file ~/dotfiles/Brewfile
brew bundle --file ~/dotfiles/Brewfile

    A new machine goes from bare to useful in one command, and when you adopt a tool you add it once.

    The trap: a non-interactive shell — a cron job, a scheduled task, or ssh machine some-command — does not read your profile, so on Apple silicon it never gets /opt/homebrew/bin on its PATH. Everything works when you are typing and fails when it runs by itself, reporting command not found for something you can plainly see installed. Scripts should set their own PATH rather than assume yours.

    And: casks are GUI applications. Put them on the machine you sit in front of, not the headless one, where they are weight with nothing to show.

  4. 4

    Work that survives the lid closing

    tmux — a session on the far machine that keeps going when you disconnect.

    Without this, every long job is hostage to your laptop staying awake. Close the lid, lose the build. With it, the work lives on the machine doing it:

    ssh mini
tmux new -s work      # start it there
# Ctrl-b then d       # detach; the work keeps going
tmux attach -t work   # come back, from anywhere

    This is the single biggest change in how remote machines feel. They stop being fragile.

    The trap: tmux has to run on the remote machine. Starting it in a local terminal and then SSH-ing from inside gives you a session that dies with your connection, which is the exact thing you were trying to prevent. SSH first, then tmux.

  5. 5

    A screen, when you need one

    Screen Sharing — already in macOS, no install, no account.

    In Finder, Go → Connect to Server (⌘K) and enter vnc://mini. You get the actual desktop.

    Most of the time SSH is better — faster, scriptable, works on a bad connection. But some things only exist on the screen: a permission dialog, an installer, a first run, an app that has decided to show you a window. Those are not stubbornness on your part; they genuinely cannot be done over a shell.

    The trap: macOS privacy prompts appear on the machine’s own screen and nowhere else, so a script that needs Screen Recording or Full Disk Access will sit there having silently failed while you stare at an SSH session with no error in it. Grant those over Screen Sharing, once, before automating anything that needs them.

    And the honest limit: if a machine is wedged before the operating system is up, neither SSH nor Screen Sharing can reach it, because both are software running inside the thing that has not started. That is what a hardware KVM is for, and it is the only thing that is.

  6. 6

    Somewhere for the agents to live

    Herdr — a terminal multiplexer that knows what an agent is.

    Once coding agents are doing real work, the question stops being “is it done” and becomes “which of these is waiting on me.” tmux will happily keep four agents alive and tell you nothing about any of them; Herdr shows each one as working, blocked, or done, and its sessions detach and reattach over SSH the same way.

    It runs the agents on one machine, which is the natural complement to seeing them across all of them — and it is where Little Herd stops being optional.

Now watch the whole thing.

Six machines set up this way are a herd, and a herd is exactly the thing nothing on your Mac can show you. Little Herd puts all of them in one small window — what each is doing, how full its disks are, and which agent is running where.
